# Native styled block acceptance — closed controller preparation

This is a separately reviewed source preparation for the two NativeUI methods
published in `7380a797d13b279b6d19e43ade7af1929089b8ef`. It does not contain an
admitted App, a successful Apple producer receipt, a UI test result, or visual
acceptance. The execution gate is closed before input reads or output creation:
`READY_FOR_EXECUTION = False`, and the future source, shared controller and
canonical admission pins are all `None`.

The existing App8f2, its unsuccessful/pending producers, historical App15
evidence, and the previously published NativeUI19 controls remain separate.
This package does not reopen or repin any of them.

## Owned live-size coordination

The same original controller owns the xcodebuild process, every simctl command
and the fresh simulator. There is no second simulator service or independent
controller. The actual test-runner bundle comes from the admitted original
descriptor and its Info.plist; its installed App/data containers must remain
under that exact owned UDID. The original Anytype executable reader remains
unchanged. A separate, reversible specialization changes only its root-name
guard to the descriptor-selected runner executable, preserving all original
Mach-O, declaration and alias checks.

The runner writes two bounded private requests: `expanded` and `restored`.
The controller retains each actual request before parsing it, rejects aliases,
wrong permissions, stale nonces, foreign invocation/device/runner identities,
and changed native reads or selections, and only then issues the finite
`simctl ui <owned-UDID> content_size <size>` operation. The exact installed
simctl help and original setting parser are retained source references. The
response contains the actual command readback and its digest, and is published
atomically without overwriting another file. The original Swift method still
has to observe the real mounted fonts/category; a response alone is not UI
acceptance.

The first runtime review found **STYLED-RUN-01**: the original `run()` can raise
after Popen but before its ordinary termination branch, for example when a
command receipt cannot be written. The correction is an explicitly described
runtime adapter, not an executed-behavior equivalence claim based only on an
unchanged function body. It uses an isolated copy of the original function's
globals to capture the exact returned Popen before any original receipt I/O.
It preserves the original function's code and the original73bb lifecycle
helper. Shared globals are not monkeypatched. A second review found that
protecting only the XCTest worker left six live-size helper call sites outside
that boundary. The final implementation binds one `OwnedCommands` registry
after the original lifecycle helper is loaded and before the first command.
Every command in both new stages uses that registry, including device setup,
runner-container lookup, setting writes/readbacks, enumeration, both XCTest
executions, result collection and final cleanup. The original historical
profiles are unchanged.

The adapter retains a positive original group-absence observation before any
later bookkeeping and never probes or signals that historical PGID again.
An early exception passes through bounded cleanup/reaping of the captured
owned child and the original group observation. A later cleanup or closure
receipt failure cannot replace the first original exception. An exited parent
with an unresolved surviving group remains failed custody. In that case the
controller withholds settings restoration, further device observations,
sandbox operations and shutdown, and records that the owned simulator was
retained. Closure aggregates every captured command: a closed XCTest process
cannot hide an unresolved setting command. Python thread return is explicitly
separate from process closure.

The independent `styled-execute-closure.json` records the original runner and
lifecycle identities, the runtime adapter identity, actual captured PID/argv,
first exception, reaping and group observations. Its pin is retained in
`styled-finalization.json` and the main receipt. Every other command has its
own closure record, and the main receipt pins the final
`styled-owned-commands.json` after the last command. Successful custody alone
does not establish a successful XCTest result. The collector's original
`native-styled-live-control/v1` schema remains unchanged. After positive owned
closure, a setting that may have changed is restored and read back in the
finally path, even when the setter or XCTest failed. Restoration/evidence
failures keep the overall result failed.

All original failures, review findings, earlier source variants and affected
retries are retained. The first lifecycle regression attempt passed two
methods and encountered one harness module-identity error; the affected method
was retried after constructing the class from the exact module under test.
That harness correction did not change runtime code. No old acceptance result
is converted into a new pass.

These outcomes belong to their individually pinned source variants. The
earlier controls are not presented as executions of the final registry source.
The final source cross-wire and independent runtime/collector reviews are
separate from these portable controls.

The source/portable controls qualify only the preparation's refusal,
provenance, parsing and failure boundaries. Their fake Popen records and
synthetic observation fixtures are labeled as such. No backend process,
simulator setting, App, Native call or Apple build was used for these controls.
The retained local control commands are evidence of the paths at which they
actually ran; relocating the scripts is not represented as a new execution.
Prior materializations, reviewed source variants and the failed harness source
are retained in a digest-bound compressed evidence record. Its per-member
original path, byte count and SHA-256 preserve the exact bytes without
silently rewriting old script paths. The publication handoff identifies the
current executable sources, all review records and every retained control.
