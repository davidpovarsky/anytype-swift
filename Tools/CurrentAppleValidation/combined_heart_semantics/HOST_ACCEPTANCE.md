# Combined F/T5 current-host functional acceptance

`combined_host_acceptance.py` consumes the same source-bound, successful combined app and complete original UI products as the E controller. It does not compile or modify app source. The required configuration is **Debug-Anytype**; every receipt leaves Release, full F, full T5, the UI01–UI12 matrix and physical-device acceptance unclaimed.

## Fixed execution plans

- `first-editor`: original `PinkhaStage1AcceptancePreparationTests/prepareRealApplicationState()` first, then the three original editor UI methods and `testUnifiedEngineSwitchRetainsHeartDocumentAndColdReopen`.
- `coherent-functional`: editor first, original Return3, quote/drop, properties/set with the original stopped-store installation and native postflight, host11 methods/12 cases, pending-nine, quote freshness, and original T5 native/UI plus Hebrew light/dark R08. RTL preparation is tracked separately, preserving the original nine-series inventory.
- `t5-only`: the four original T5 series, each on its own new account/simulator where applicable.
- `remaining-editor-journeys`: quote/drop and properties/set.
- `return-controls-only`: original three Return controls; requires a concrete affected-source reason in the admission instead of silently repeating retained acceptance.

There is no arbitrary method override. Exact compiled identifiers are enumerated before invocation, including Swift Testing argument syntax. Original fixture, lifecycle, count, native readback, timing, account-directory, credential, authority and attachment validators remain intact. Pending-nine never invokes the historical36-query body. The three additive T5 predicate modules have reviewed original-function equivalence and bind only the exact70fb runtime; existing139 entry gates are untouched.

## Admission

Start from the separately hashed actual combined producer admission. Preserve its original producer receipt/logs/source-before/source-after and full app/UI product manifests. Set `sourceRoot` to a clean immutable copy of the actual producer source and each product root to an exact original Products copy. Do not substitute an unrelated product or treat the stale retained `Current-Page154-preparation.xctestrun` as a current descriptor.

Use schema `pinkha-combined-host-acceptance-admission-v1`, `executionEnvironment: SentinelX-owned-Mac`, `buildConfiguration: Debug-Anytype`, one fixed `plan`, `appLanguage: en|he`, `appearance: light|dark`, actual installed `deviceType`, and matching `deviceFamily: iphone|ipad`. `controlFiles` must contain exact SHA256 values for these seven files: combined_host_acceptance.py, combined_heart_semantics.py, combined_heart_observations.py, combined_host_helper_pins.json, combined_t5_pending.py, combined_t5_retry.py, combined_t5_freshness.py. Keep the actual combined native/overlay/source identity. No GitHub Actions run ID is fabricated; receipt IDs are explicitly local.

Run only after the source/product/controller admission is reviewed:

```sh
/opt/homebrew/bin/python3.12 combined_host_acceptance.py --admission /absolute/admission.json --admission-sha256 EXACT_SHA256 --root /absolute/new-owned-attempt
```

The editor configures and independently reads back the **opposite actual simulator device language after reboot**, then the original app test uses its requested language. Code-carrier hashes are checked on installed apps. R08 separately checks real appearance and fixed-Large settings before and after each actual original Hebrew method. These checks do not claim every UI01–UI12 configuration, VoiceOver, orientation/window transitions, whole-index completeness, native ACL coverage from host callbacks, or physical-device results.

## Retention and ownership

Original descriptors are immutable; only narrowly scoped copies select methods and inject their original fixture environment. Full app/UI Products inventories stay unchanged. Each command has an owned process group, bounded timeout and a live2GiB guard. Each fixture uses a newly created simulator; independent lanes can continue after a failed lane, while no dependent UI/postflight runs on failed preparation.

Every original xcresult, failure attachment, private native receipt and command result is retained. Each F simulator is shut down and its account retained for review/recovery; automatic deletion is deliberately absent. Private payloads and credentials remain under mode0700 owned directories and must not be published as tracked source. Failed E continuations also now retain their simulator; E deletes only after all six methods and complete final private retention succeed.

## Source controls

`qualify_combined_controller_sources.py` checks the extracted admission statements with only three explicit local-variable aliases, exact descriptor inverses, rejection of empty/foreign/duplicate/disabled enumerations and skipped/zero/failed named results, strict combined runtime admission, and missing-sandbox rejection after app execution. These are pure collector/source controls, not native or Apple acceptance. See the accompanying `f-controller-controls.json`, `f-helper-import.json` and `combined-t5-source-review.json` receipts. The original live E attempt remains bound to its prior b1c26 controller and original results; no receipt is rewritten.
