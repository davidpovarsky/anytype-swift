## Scope

Two real native processes each call WalletCreate and AccountCreate into an
independent empty private root. No recovery key, database, ACL record, read key,
object tree or private operation bytes are copied between them. The controller
passes only public account/peer addressing, operation identifiers and hashes,
and signed ACL head identifiers. The member receives its encrypted read key
and all actual records through native SpacePull/ObjectSync.

The fixture configures a static owned peer route with the existing
PeerService and PeerStore APIs. This is a deliberate network routing input;
it does not qualify mDNS token discovery, invitation UX, coordinator consensus,
or remote Space participant RPC mutations. LocalOnly has no responsible
coordinator nodes, and the real client AclAddRecord RPC requires them.

The owner creates and validates real signed records with the original
AclRecordBuilder and SyncAcl. AddRawRecord persists each record, broadcasts it
through the unchanged native sync service and retains the native updater.
No authorization verdict or record is injected into the member.

| Stage | Required observation |
| --- | --- |
| Independent wallets | Distinct account IDs, peer IDs, private keys, database inodes, processes and network namespaces |
| Writer grant | Exact signed ACL head and record hashes converge; member reads original canonical bytes and author provenance |
| Reader change | New signed role head converges; the member remains a reader of the same original operation |
| Actual detach | Docker disconnect and native no-interface observation both hold |
| Offline read | Last known locally verified Reader authority remains usable |
| Unseen revocation | Owner removes member and rotates read key while member remains detached; member still observes the old head |
| Reconnect | Same native process rejoins its owned network and obtains the exact revocation head through native ACL sync |
| Publication fence | A real read prepared before revocation cannot publish its snapshot after the native revocation is observed |
| Current byte RPC | Generated authorized-operation read returns typed denial/invalidation with no snapshot |
| Shutdown | Both native accounts stop, return NOT_LOGGED_IN with no payload, and the selected Go test exits successfully |

The offline result makes no claim that a disconnected client knows an unseen
revocation. The fence is tested after the signed change has actually reached
the client's loaded ACL.

## Test-only adapter

`core_fixture.go` is an additive Go overlay file compiled only with
`pinkha_acl_transport_fixture`. It exposes the original native prepare and
finalize boundary to this separately built test binary. It supplies no authority,
snapshot or replacement result and changes no existing native source.
The member captures the prepared value while disconnected, releases the native
preparation leases, waits for the real signed revocation and calls the original
finalizer. The ordinary generated byte entry is then checked independently.

The executable binds the complete fixture source closure, original139 source
inventory, compiler, native image and current controller commit. The original
product inventory is verified before and after compilation.

## Execution and evidence

Dispatch the inline `independent-member-acl` route in
`.github/workflows/torah-inspector-ipados27.yml`. It uses Linux x86_64 and the
existing pinned Go1.26.5 musl image; it does not use the Apple runner or add a
reusable-workflow reference. Existing central jobs remain unchanged.

Only owner-labelled fresh Docker resources are created or removed. The test
binary is mounted read-only, each process can see only its own private store,
and the bridge is internal. Success requires original method logs, source-bound
native receipts, original protobuf responses, observed process identities,
matching native ACL records, exact zero-payload denials and successful cleanup.
Every exported runtime file is scanned against both independent wallets'
actual recovery material. Private account data is excluded from exports.

The live member reconnects through Docker IPAM on the same owned internal
bridge. Its address may change; the controller records the initial and actual
reconnected addresses and matches the latter to native interface receipts.
Container, process, namespace, sandbox and peer identities must remain
unchanged. Successful compilation caches are saved before native execution so
a later acceptance failure does not discard the dependency cache.

compiled successfully and reached the offline unknown-revocation observation,
