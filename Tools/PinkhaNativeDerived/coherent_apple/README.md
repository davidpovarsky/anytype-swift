# Combined Heart Apple authority proof

This lane admits the exact 139-file native composition from successful run
`45026227924`, source `b2fc3804426067dd1ec8318d6ea92a4bcb8e9545`. It checks all
43 original evidence files against a frozen manifest and applies the original
full patch. It does not rerun the previously qualified native cases, regenerate
protobuf, or repeat the previous 25 Swift/iOS methods.

## Two distinct frameworks

The first build uses only the qualified production source. Its single ARM64
simulator slice is packaged separately with `PinkhaNativeHeartBuild.json`.
The receipt's `PASS` means the framework build passed; it explicitly records
`APPLE_FRAMEWORK_BUILT_NOT_EXECUTED` and `NOT_RUN_BUILD_ONLY` for runtime use.
This artifact is not a device, universal, Release, or full App acceptance.

The second build reuses the same native compilation cache but includes an
explicit `pinkha_coherent_apple_fixture` tag. Three additional files implement
a bounded one-shot bridge plus a mechanical translation of the two originally
qualified account fixtures. The production139 files remain byte identical.
The fixture framework and its receipt have separate hashes, names and artifact
identities; this binary must never be installed as the production runtime.

The translation preserves every original assertion and uses a narrowly tested
stdlib-only assertion adapter, so it adds no runtime module dependency. The
original raw-call seam additionally records the exact revoked ObjectSearch and
ObjectShow replies. No permission, ACL identity, event updater or native RPC is
mocked or replaced. The bridge accepts no filesystem path and refuses an active
account. It creates one local-only disposable account in its own temporary root.

## One new actual XCTest

`CoherentHeartAuthorityTests/testActualCombinedLibSignedAuthorityAndSharedSwiftDecoding`
executes only the new combined case on an owned iPad simulator. The actual
native journey proves Owner and Reader positive reads, signed removal with
read-key rotation, denial on the same account/cache, and AccountStop. The same
actual T2 responses then pass through the unchanged shared Swift decoder;
Owner/Reader variants must match and the removed response must throw the exact
typed denial. Original T5 Search/Show raw replies are independently parsed to
require error2, the authority sentinel, no object/rows and zero total.

This does not prove network ACL delivery, offline discovery of revocation,
fresh iOS process reopening, production-binary execution, full app navigation,
automatic T2-to-T5 materialization, device acceptance or Release acceptance.
Those claims remain separate gates.

## Original evidence and source binding

The evidence artifact retains paths under `proof/` and `controls/`:

- `proof/build.json` binds source139 and both distinct framework byte maps.
- `proof/production/custom-heart-build.json` is the packaged production receipt.
- `proof/production/runtime-artifact.json` binds that receipt and archive.
- `proof/native-source/` retains the exact original full patch/inventory.
- `proof/host/receipt.json` requires exactly one passing named XCTest, no skips.
- `proof/host/coherent-heart.xcresult` is the original actual Apple result.
- `proof/host/actual.json` is the original Swift/native evidence attachment.
- `proof/host/native/` contains the eight exact exported native files, including
  three T2 replies and revoked Search/Show replies. Both disposable account
  secrets are checked against every export before it leaves the native fixture.
- `proof/host/control-source-before.json` and `control-source-after.json` bind
  the controller and copied shared Swift sources. Their canonical digest is in
  the host receipt. The copied framework is rehashed after execution.

Consumers must require the actual successful `coherent-heart-apple` route,
source/run/attempt binding, original xcresult and every original evidence/hash
before admitting the production artifact. The fixture's successful execution
does not turn the unexecuted production slice into a shipping acceptance.
