The optional reusable input is `crash_after_commit: boolean = false`; it requires `scenario=offline`. Root owns the parent route `t2-native-clients-crash`. Bootstrap and ordinary offline selections retain the prior 42-control set and four passing client phases. `TestT2NativeClientCrashCommitPhase` publishes its arm receipt only after the actual generated append entry returned into a withholding byte wrapper, native signed storage proves the one new commit, and the request/source/account/store facts have been checked. It calls no post-commit ReadTarget and never has a successful natural return. Its native callback never decodes the response. Only the exact owner/ID/PID/namespace/start identity can be killed within the arm's 30-second window. OOM, earlier exit, replacement, normal PASS, missing commit or any wrong shape is failure.

The kill and wait commands each receive the smaller of the remaining phase and arm budgets. One monotonic deadline fixes the arm window; subsequent wall-clock samples can shorten it but never renew it. After wait, the original owned container must be inspected and its stopped state observed before both deadlines. The receipt records the actual observation time and original arm deadline. A late kill return, late wait or late stopped-state observation remains failure, even if the eventual exit is 137. Log collection follows this bounded termination proof.

It observes persisted signed history before ReadTarget or retry, checks the complete retained baseline plus the new canonical native-author claim, and hashes the actual retained encoded bytes inside the second generated entry.
