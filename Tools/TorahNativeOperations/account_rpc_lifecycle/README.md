# Three real-account generated-byte lifecycle races: local candidate

Status: **LOCAL CANDIDATE, NOT COMPILED, NOT DISPATCHED, NOT NATIVE ACCEPTANCE**.

The candidate is based on frozen application source `16b7493fa05bdc3abbae190c6e6c364c81874eea` and Heart `d98420b1113536afd08cde6de9a5816f6d27ffff`. The original component/registry/RPC/client lanes and their seven native-client fixtures are unchanged. This directory is separate from that frozen control tree. App capability stays OFF.

## Three cases

| Case | Deterministic observation | Required original outcome |
|---|---|---|
| First ADD loses to block deletion | Pause the real generated-byte append after successful native target preload and before acquiring settings/target leases; complete the actual generated BlockListDelete; release the same append once. | TARGET_UNAVAILABLE, nil receipt and exact ErrUnknownTreeId + nil private storage. No private root is installed. |
| Existing-root append wins before block deletion | Pause inside the original final ACL read hold immediately before its actual storage AddAll. Start real generated BlockListDelete and observe the exact same target SmartBlock's lock attempt inside `cache.Do[basic.Unlinkable]`. After forwarding the storage call once, pause again and read the committed bytes from the already captured Space. | Deletion acquires the target only after the durable write; one new signed entry extends the original two-entry history. Both the unchanged CREATED append result and successful deletion are required, without asserting their response order. Later generated read/retry deny the missing target and raw history remains identical. |
| Existing-root append wins before AccountStop | Pause at the same durable boundary, start real generated AccountStop(RemoveData=false), and observe its original writer-lock attempt and acquisition on the same application.Service instance seen under the append's native app lease. | Writer acquisition follows durable storage and the native append's result; actual Stop succeeds; later generated read/retry return NOT_LOGGED_IN with no result. |

The two commit cases use an already initialized private root and preserve both original signed-entry hashes when the third entry is committed. The first case specifically tests rejected first-root creation. Account creation, disposable Space/Page/block creation, deletion, append and shutdown use the real generated byte APIs. Account helpers come from the existing separately pinned account-RPC fixture, without replacing its handler or registering a substitute proxy.

The `append-native-return` event is emitted after the original host append returns while the outer native handler still owns its application lease. The handler then returns and releases that lease. The generated RPC subsequently converts/encodes the already computed result; AccountStop may acquire its writer lock before that later byte encoding finishes. This test requires the original native result and durable write before writer acquisition. It does not require the caller to receive response bytes before Stop begins closing the account.

## Exact test-only instrumentation

`test-composition.patch` instruments five source files only in the Go compile overlay:

- `core/pinkha_torah_operations.go`: signal/wait after native preload and before native lease acquisition; signal after the original host append returns.
- `core/block/editor/torahops/native_commit_guard.go`: signal/wait immediately before and after the original `s.Storage.AddAll(ctx, changes, heads, snapshot)`. That original call remains once, inside the original final ACL hold, with the same context, guard token, author, bytes, heads and snapshot. The original error returns unchanged. Original target/settings release still occurs later in its existing position, after the ACL unlock and durable witness.
- `core/block/cache/cache.go`: signal immediately before and after the original target `sb.Lock()` in generic Do. The filter requires the actual previously loaded SmartBlock pointer, object ID and `basic.Unlinkable` generic interface. The callback and original Unlock defer are unchanged. This is the real BlockListDelete path; clientspace.DoCtx would have observed the wrong path.
- `core/application/account_stop.go`: signal around the original AccountStop writer `s.lock.Lock()`, after the unchanged cancelStart logic. No lock is released or replaced.
- `core/application/pinkha_torah_lifecycle.go`: signal while the original successful app lifetime RLock is held. The observer compares the actual Service pointer with the Stop events in memory; pointer values never enter a receipt.

The new helper package contains only a mutex-protected capture, exact filters, channels and bounded waits. It invokes no application callback and cannot return a native result, rewrite a context, replace an identity, authorize anything, retry, or acquire/release a native lock. All waits have a fixed 20-second bound; owner-side event waits have a 15-second bound. Gate timeout, missing event, wrong pointer/type, duplicate stage, extra call or unexpected event order fails the fixture. There are no sleeps used to infer a race ordering.

The pre-generated protobuf request is marshaled once on the owner goroutine. An isolated goroutine passes those exact bytes once to the unchanged generated function and sends back its exact response bytes. The test does not run Fatal/FailNow inside those goroutines or update the original non-thread-safe RPC-count map concurrently. No GetApp or loading cache helper is called while the Stop writer is queued. Raw history reads at the durable barrier use the already captured Space and its storage API directly.

## Build composition and verification remaining

`prepare_candidate.py` verifies the three published product overlays against their registration inventory and the two upstream files against exact pinned Git-object hashes, then creates the candidate overlay and its hash manifest. `materialize_test_overlay.py` is a future build-input adapter: it checks all original source bytes and all separate candidate hashes, refuses overlap with existing replacements, and writes a new compile-overlay JSON. It never overwrites any of the five product source files. The new helper package gets only an empty directory in the disposable build tree so Go can discover its overlaid source file.

The existing original account-RPC build must be composed first. The candidate adds `lifecycle_observer.go` at `util/pinkhat2test/lifecycle.go` and the new service test at `clientlibrary/service/pinkha_t2_native_rpc_lifecycle_test.go`. A future reviewed lane must link `t2LifecycleFixtureSHA` to the frozen candidate manifest hash and invoke only `TestT2GeneratedByteLifecycleRaces` in a new owned account root. It must retain the build/source receipts, original native test log, lifecycle JSON, exact source hashes, private-secret exclusion scan and owned cleanup receipt. No such lane is dispatched by this candidate.

Required ownership variables are `PINKHA_T2_LIFECYCLE_ROOT`, `PINKHA_T2_LIFECYCLE_REPORT`, `PINKHA_T2_LIFECYCLE_NONCE`, `PINKHA_T2_LIFECYCLE_OWNER_TOKEN` and `PINKHA_T2_LIFECYCLE_FIXTURE_SHA`. The owner document must have this protocol and `synthetic_only=true`; the account root must be empty and named account-root. Wallet secrets are only retained in the controller's private sensitive-needles file, never in the lifecycle report.

All seven Go inputs passed the existing native `gofmt` parser through bounded stdin/stdout calls, with an identical second formatting pass and no candidate source files written on Windows. Only the two added Go files required formatting; the five instrumented overlays were already identical to formatted output. Native compilation and actual race execution remain NOT_RUN. No Windows checkout, build or cache operation is permitted while C: headroom is critically low. Local source checks, formatting and exact overlay composition do not establish native execution.

## Explicit limits

The generated byte entry uses context.Background and exposes no caller-controlled cancellation context. This candidate preserves original contexts and does not claim generated-byte cancellation; typed/native cancellation evidence remains separate. It does not exercise signed settings deletion, template uninstall, standalone Space.Close, account switching, separate-member ACL revocation, power loss, new-engine parity, iOS or full T2 acceptance. It does not create any public product API or change backup, compaction, ordering or canonical operation formats.
