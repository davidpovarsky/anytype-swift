# Actual native process-crash and HTTP acknowledgement-loss fixture

This opt-in Linux fixture adds two acceptance methods to the exact prepared inline HTTP candidate. It changes no production or previously qualified test file. The source manifest identifies the reconstructed candidate, two added files, compiler profile and exact selectors. Source preparation is not runtime acceptance.

## Frozen source and domain

Any candidate tree: 0445217b25b4f4fcf4d2ce86e3a4eecfcfc5cd10. SDK candidate tree: 8b9df2cdcefb5aee3973df11a326652f5a2378f4. Each full patch is applied independently to its exact original upstream commit. All 850 candidate Any files and 683 SDK files remain exact. Only two Linux test files are added under the linux and pinkha_inline_recovery build constraints.

Each case uses a fresh ordinary page owner, the existing prepare/commit contract, the existing 4095-byte deterministic binary content and Unicode filename semantics. The exact specification bytes, source key, intent, store/account/Space binding, fingerprint, root ID, signed change ID, file ID and record IDs remain original through every retry. General file capability remains zero and network verification remains false.

The helper boots unchanged OpenSDK and buildEcho paths with the same pinned local node configuration. Its eight node addresses are redirected to an owned loopback listener that immediately rejects connections; LAN discovery, global P2P and push are explicitly disabled. File operations use the unchanged production SDK and actual native store.

## Process ownership and persistence

The selected parent creates fresh private-store and safe-evidence directories, both mode0700, without replacing existing paths. Wallet keys and original SDK process logs remain only in the private directory. The original store is retained for failure investigation and excluded from public artifacts.

Each child is the actual compiled test binary, invoked only with TestPreparedInlineFileRecoveryChild in a new process group. It verifies the original parent PID, its actual PGID equals PID, private-directory owner/mode, launch nonce and monotonically sequenced inherited-pipe commands. The parent records actual PID/PGID and requires a distinct PID on each reopen.

A crash boundary is accepted only after the parent sends SIGKILL to that exact owned process, waits for its actual signaled process status, verifies signal9 and exact-PID absence, and finds no orderly-close markers. Safe receipts preserve the raw WaitStatus. The child has no deferred SDK teardown. Only an explicit final close command invokes orderly teardown and writes those markers. The two final orderly closes are cleanup and never crash evidence.

## Reservation and root crash journey

TestPreparedInlineFileActualProcessCrashRecovery performs this sequence:

1. Prepare through real loopback HTTP; require file-prepared/prepared. Independently read native status, Files.List and Files.Stats, with zero visible rows and unavailable file content.
2. Kill that live process with SIGKILL. Open the same wallet/store in a distinct child and require the exact original preparation and native status.
3. Send the original commit bytes over HTTP. Require file-root-committed/prepared with unchanged IDs and still zero native file rows.
4. Kill that live process with SIGKILL. Open the same store in a third child and require the exact original root-stage receipt before another mutation.
5. Commit the original row, independently enumerate exactly one native row, and read exact metadata/plaintext via native Files.Get/Open. Replay the identical commit and repeat independent native count/content checks.

The production reservation boundary is PrepareMigrationInlineFile returning after ReserveInlineFile, which performs the existing journal durability barrier. The first commit returns only the native root stage; MigrationInlineFileState explicitly advances at most one stage. This fixture does not modify those barriers or inject inside their transactions.

## Actual lost-acknowledgement journey

TestPreparedInlineFileActualLostHTTPAcknowledgementRecovery uses a separate fresh store:

1. Prepare and commit the original carrier root over real HTTP. Confirm the native root stage with zero visible file rows.
2. Arm one fault with the exact parent nonce, commit path and original request-body hash. Every other request uses the ordinary handler.
3. The actual client writes the commit request over a fresh TCP connection. The wrapper calls the unchanged real Echo route and holds only its outgoing response bytes in a bounded buffer.
4. Require the real handler's actual200 complete/committed receipt. Independently read native Status/List/Stats/Get/Open before losing the response.
5. Hijack the real client connection, require no response bytes in its network buffer and close it without copying the held response. The parent requires a real written request, EOF/reset, no HTTP response and no first response byte. A timeout or fabricated failure cannot pass.
6. Kill the committed child with SIGKILL, open the original store in a distinct process, and require the original complete receipt before retry. Replay the original prepare and commit bytes. Native row count remains one and original plaintext/IDs remain exact.

The captured response is the actual handler result, not a constructed successful receipt. Both the server's post-commit native observation and the independently observed client transport failure are required. The fault affects only that fresh owned loopback connection.

## Execution and evidence contract

The build phase verifies every Any/SDK Git blob and committed fixture/controller input, compiles once with Go1.27.4 Linux ARM64/glibc, GOMAXPROCS=1, -p=1, -mod=readonly and GOPROXY=off, and preserves the original binary/hash plus actual method registration. Compilation executes zero product methods.

The execution phase admits only that unchanged binary, source closure and source plan. Go test2json receives exactly the two new parent selectors and count1. The separately spawned child helper is a fixture component; its starts or successful cleanup exits are not counted as extra accepted product methods.

The runner reuses explicitly supplied prior module/build caches and owns its temporary directories. It stops its owned process group on its fixed deadline, less than2.5GB available headroom or more than1GB incremental volume consumption. It never cleans a preexisting cache, worktree or service.

Original argv, environment profile, build/execution logs, before/after Git-input inventories, compiled registration and named Go start/pass/fail/skip events are retained. Safe nonce-bound observations and exact PID/PGID/SIGKILL receipts remain separate from private raw SDK logs. Only private-log hashes enter safe receipts. Original failures remain attached; source/fixture corrections receive a new attempt.

## Explicit acceptance limits

This can establish only these new Linux native/HTTP recovery scopes. It does not establish physical power-loss durability, Swift or App client behavior, Apple simulator/device behavior, notification-outbox delivery, remote network recovery, whole-Space snapshot/census, general file migration or full migration. Existing qualifications remain attributed to their original sources and are never rerun or aggregated into these two new methods.
