# Any semantic anchor Apple acceptance

The product adapter uses the existing shared semantic marker and inline-Markdown
transform, actual authorized reads and conditional native PATCH. Confirmation,
outcomes and Hebrew/English copy are shared with the Heart adapter through
PinkhaKit. Selection and native publication remain owned by each mounted engine
adapter.

This standalone controller runs exactly the two new NativeDocumentPublicationTests
methods and the new NativeLaunchTests UI journey. It uses a unique source checkout,
one owned simulator and a copy-on-write clone of the retained D3 compilation cache.
Old D3 products/results are never relabeled as acceptance for changed source.
It retains command receipts, original build/test xcresults, original descriptors,
before/after compiled products, native source binding and exact dependency hashes.
Only its own process groups and simulator may be stopped or deleted.

The SDK materialization is generated from exact Oracle git archive
6bd6036dbca16c969689a5722550a54bebc1e851, with all 5,103 file digests verified.
The Any native archive remains source-identical to producer
31ae2e63890b6e10af8413625534f6234ed263bb; this source qualification does not transfer
automatically to the later combined Go runtime.

The DEBUG UI observer is opt-in only for a valid owned UI-test scope. It reads the
actual presentation native snapshot and actual visible UITextView attributed
links, compares the independent values, and emits bounded hashes/ranges. It has no
engine calls, edits, selection/navigation actions, backend fixtures or ACK path.
The UI test itself performs normal account creation, native text selection,
Cancel, explicit Create, ordinary typing and a fresh-process reopen.

At the source checkpoint this is NOT_RUN on Apple. Heart Page154's earlier
45536229185 PASS remains bound to commit781340, and the shared presenter/resource
change requires its own affected Heart UI requalification. This does not close
broader Task E, final combined-runtime, multi-peer sync, cross-document navigation,
or physical-device acceptance.

Attempt1 stopped before any Xcode build or test: the nine copied SwiftPM Git
alternates still referred to the former D3 runner directory after its atomic
retention move. The controller now verifies the copied object databases against
the retained originals and rewrites only the owned copies' alternate paths.
All nine dependency HEADs must still match D3 exactly. The original D3 cache is
untouched; attempt1's failure and successful owned-device cleanup remain retained.

The copied cache consumes about 5 MiB of additional physical storage (both old
copies were measured and removed after matching all 631 original product files);
the retained D3 derived tree is about 1.18 GiB of logical data. With the source
already materialized, startup requires 5 GiB free, each build requires 3 GiB,
and an owned build is stopped below 2 GiB. This measured budget replaces the
initial arbitrary 7 GiB admission floor; original test gates are unchanged.

Controller and app source revisions are recorded separately. A controller-only
infrastructure repair can run against the existing clean, frozen product checkout
without duplicating that entire checkout or changing its native consumer binding.
The launch verifies the exported controller bytes against the exact Git revision,
and the execution receipt records the loaded controller SHA256.
