## Material boundaries

The guarded native claim lane has a separate signed versioned module. Normal editor reads use indexed **object logical closure**, including global conflict witnesses before folding; unrelated Space history does not consume the object bound. The diagnostic/migration whole-Space snapshot retains its declared bound and is never silently replaced with a partial snapshot.

Canonical archive export contains opaque operation payloads and native provenance, excluding derived fields and local caches. It is not a full document text/attachment archive or a Heart database converter. Import requires explicit target block and internal-Note mappings, a new native signer, complete preflight, immutable retries, and final readback. The original typed JSON domain cannot safely edit every unknown number; those cases are refused while export preserves the raw bytes.

The property catalog is display metadata. Fresh native target/type proof and the final definition/membership fence authorize mutations. Actual native15 verifies Type changes retain body IDs/styles/children, collection detach/reattach retains business values, and hide/show uses the compiled hidden preference collection without deleting data. Source/Topic/Word remain separate read-only derived outputs.

The native editor retains unsupported markup and native block types without flattening them. Marked-text IME composition, reversible formatting toggles, checked/ordered list markers, and full mounted focus/selection/Undo/drag/RTL acceptance remain open. The new root-scoped recovery object preserves local drafts and navigation across an in-process background reconnect; it does not promise unsaved recovery after process termination.

Native object/block/Note creation uses the shared protected intent journal. Unknown auto-ID results do not authorize a fresh-ID retry. Known IDs survive later journal/readback/callback failures. The real 14-case constructor probe uses memory metadata and does not replace protected Apple storage tests. Source quote text and canonical metadata remain separate operations, with the original partial-insertion behavior.

The actual Hanlin presentation receives the same guarded creator, original confirmation/router/consent/journal logic and a single account owner. Exact baseline selected-text coverage is whole selected text blocks, not character substrings. A synthetic UI owner or native HTTP probe does not establish mounted permission-sheet acceptance.

The native FTS query `שלום` did not retrieve `שָׁלוֹם` in the recorded experiment. The equivalent old Heart behavior was **not verified**, so this remains an observed native search gap rather than an established regression. See [the source-bound search receipt](../../Tools/AnyEngineValidation/evidence/search-native-v1.json).
