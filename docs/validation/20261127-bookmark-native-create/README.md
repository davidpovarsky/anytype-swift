## Native contract

The new advertised capability is `nativeBookmarkObjectCreate: 1`. A read-only POST to `/v1/spaces/{spaceId}/pinkha/bookmark-create-frame` accepts a selected Type and requested collections. The engine derives the complete Type, editor-part, property-owner, and property dependency set. It validates the existing layout-11 Type and its source-URL property at one coherent native definition snapshot. Collections are the sorted unique requested set plus that mapped owner; a client does not choose a substitute dependency set.

The response contains an opaque canonical base64url frame, bounded to 65,536 raw bytes and 87,382 encoded bytes. The optional `bookmarkDefinitionFrame` field on the existing `/v1/spaces/{spaceId}/pinkha/objects` create route binds the signer/account, Space, existing generation, complete dependencies, signed heads, selected Type and property identity. Unknown, duplicate, malformed, foreign, obsolete or incomplete frames fail closed. The generation read uses `FindId` only and never recreates an absent generation record.

The final condition remains inside the original sorted definition locks through the existing current-writer durable append. Ordinary create without the optional field keeps its original behavior. This adds no schema-bootstrap fallback and no second creation subsystem. A root created before later bootstrap failure remains a known uncertain effect; callers retain its identity and do not retry or replace it silently. Post-create readback alone is not described as atomic selected-descriptor validation.
