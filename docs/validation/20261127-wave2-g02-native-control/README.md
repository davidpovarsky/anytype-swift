## Fixed adapter API and selection

`run_native_phase(consumer, directory, udid, phase, startup_environment, seed_ui_ref, *, baseline_ref=None, unlink_ui_ref=None)` accepts only `baseline` or `postflight`. Artifact refs are exact canonical `{path, sha256}` pairs. Both phases use the original `Consumer.stage` with exactly `AnytypeTests/TorahWritingPropertiesReadbackTests/observeOriginalWritingProperties()` and the original 300-second native-method allowance. Neither an entire suite nor another preparation or historical T5 call is selected.

Before selection and after acceptance, the adapter requires the exact bd988 full source, 0f862 suffix and unchanged 84,286-byte 7ec7 preparation prefix. It invokes the existing reviewed `native_compiler_witness.py` aaa40880 with RTL witness dependency 80ebc560. The proof pin must be `producerReceipt.nativeCompilationProof` from the already successful common admission. Actual source/file-list/swiftc evidence is required; the older 7ec7 file and source declarations alone are rejected.

The actual native stage invocation, descriptor bytes, enumeration, one-case result, original command record/stdout and owned UDID are retained. `INVOCATION_SHA256` in the eleven shared startup keys remains the original NativeDerived preparation hash; the native phase invocation receives its own separate ref. The original raw installed fixture owns `FIXTURE_SHA256`, while the UI environment is compared as decoded JSON. The adapter preserves the original startup environment and explicitly zeros all nine preparation/account flags and `PINKHA_TYPE_PRESERVATION_POSTFLIGHT`. It never supplies a fabricated `SIMULATOR_UDID` environment value in place of the actual process runtime.

## Receipt custody and semantic scope

The native Swift reader remains the semantic comparison authority. Its full native JSON snapshots, canonical bytes, actual Word/Tag identities, Source/Topic/native fields and allowed clock changes are not recreated by a substitute Python model. The adapter checks receipt identity, scope, raw hashes, actual three writing IDs, exact phase inputs, process identity and directory custody around that actual compiled XCTest.

All fixed output names must be absent before the native invocation. On success, the accepted receipt must match the retained pre-comparison observation in every field except status. The compact baseline must refer to the actual full baseline/seed hashes and the same real native document and Tag IDs. Postflight requires the same account and native directory identities, a different native host PID, and exact baseline/unlink hashes. The unchanged four-stage controller separately performs its five stopped-App/directory boundaries.

The baseline return contains `status`, `phase`, `sourceContract`, `actualTest`, `invocation`, `seedUI`, `observed`, `baseline`, and `uiBaseline`, plus bounded custody details. Postflight replaces `uiBaseline` with `unlinkUI` and `postflight` while retaining the actual baseline ref. No actual native receipt is claimed by this source-only publication.

If XCTest or its receipt check fails, emitted `*-observed-<TOKEN>.json` bytes are still copied unchanged. They may be malformed or semantically rejected and remain failed evidence. Missing optional-after-failure outputs and later copy failures cannot replace the first XCTest error, and qualification never converts such a stage into PASS.

Independent review found a further failure-retention hole in the first adapter draft: final receipt-directory creation or the final JSON write could replace an earlier stage exception. The fix adds one shared `save_result` guard used by the native adapter and the outer four-stage controller. It preserves the original exception object, appends the secondary save error to retained state when possible, and chains/notes the later error if the receipt itself cannot be saved. If there was no prior failure, a save error correctly fails the otherwise successful stage. The original F cleanup/finally block remains byte-identical.
