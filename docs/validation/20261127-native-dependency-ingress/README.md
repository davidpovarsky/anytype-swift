## Operation and barriers

The root-reviewed plan must name the exact immutable control commit and exact bytes of the controller and registered workflow. The workflow checks out that commit into an absent run/attempt-specific path, records HEAD and a clean tracked/untracked status, and preserves all older checkouts. `before` verifies the fixed original path, entire compressed archive, all seven regular members, metadata and transformation receipts. The pinned existing upload-artifact action then reads that one existing file directly; no temporary archive or copy is created on the Mac. `after` independently repeats the complete check and requires the original inode, ownership, mode, timestamps and bytes to match the before receipt before issuing an export receipt.

The Python controller creates no child process or FIFO. Therefore it owns no producer PG that could outlive its terminal receipt, and it sends no process signals. File descriptors are scoped with context managers. The existing artifact action owns its upload streams; a failed or cancelled action cannot reach the subsequent success step. Its finalized ZIP is transport only: a later consumer MUST independently hash the downloaded ZIP using the actual artifact identity, require its sole file to be `native-dependencies.tar.gz`, and requalify the full55,038,316-byte a20 content and seven original members. This requirement also rejects a mid-upload mutation even if a ZIP was finalized. No artifact ID alone constitutes native acceptance.

Each invocation preserves its first failure. Receipt IO errors cannot replace that failure. Original stdout, stderr, checkout observations, plan and every created receipt are retained by an always-run evidence action. The controller's before/after claim files are exclusive and never overwritten or replayed.
