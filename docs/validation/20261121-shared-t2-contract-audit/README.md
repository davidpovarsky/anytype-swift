# Shared T2 contracts and remaining acceptance

Review date: 2026-11-21. This is a source and requirement audit, not a new runtime acceptance receipt. Full T2 remains unaccepted and its app capability remains OFF. Existing accepted evidence must be reused where its inputs and behavior are unchanged.

That adoption does not turn every suggested method name or storage implementation into a requirement. Atomic identity, authorization, preservation, bounded reads and the listed acceptance behaviors are requirements. The proposed API spellings, physical host layout and use of a particular store implementation are design choices. Omissions remain explicitly open until a reviewed alternative satisfies the behavior.

## What can be shared now

Both implementations already use the same v1 canonical operation domain, length-framed field order, stable operation identity and content-derived claim identity. Both retain concurrent variants and quarantine a logical operation collision before applying observed removals. Neither should introduce a different wire representation to repair an editor, presentation or acceptance-harness defect.

The shared Swift boundary should own operation identity validation, complete-result validation, scope/session binding, reachability/error semantics and display policy. Engine adapters remain responsible for their actual native transaction, signed history, ACL checks, object lifecycle locks and provenance. A shared controller cannot replace these engine-specific authorities with a Boolean from the caller.

Any's active store is `AnyGuardedTorahOperationStore` / `AnyGuardedTorahClaimsRepository`. `AnyNativeTorahOperationStore` / `AnyTorahClaimsRepository` is an earlier generic records path and does not establish the guarded native authority contract. Likewise `AnyGuardedTorahIndex` is the active native indexed path; `AnyTorahRelatedDocuments` describes an explicit bounded fallback and must not be credited as native indexed acceptance.

## First reviewed implementation: authorized operation read

Architecture review approved an additive read contract with the following boundaries. Existing append and read-target semantics, canonical version, current runtime pins and full-T2 enablement are unchanged.

1. The request names one explicit Space and one validated 32-character lowercase hexadecimal operation ID. The native adapter derives current account identity/session generation, root identity and authority; none is accepted as an authorization assertion from a request.
2. A successful response contains the complete logical-variant closure, exact canonical operation bytes, native creator/change/ACL provenance, current target reachability and an engine-bound local snapshot token. There is no selected collision winner.
3. Current account/Space lifetime, current read ACL, the actual private root and every implicated target are fenced. Candidate discovery may precede loading target trees, but the final locked snapshot must repeat the query and reject changed dependencies. One denied or ambiguous variant target rejects the entire result before payload release.
4. `liveDocument` and `liveBlock` describe current verified eligible target state. `unreachableBlock` means a still-live, currently authorized eligible document's verified graph does not reach that block. It does not claim deletion or historical existence. A malformed graph, type or authority state is an error, not an orphan result.
5. An absent/deleted whole target object returns typed `targetStateUnavailable` without payload until the engine proves a signed deletion witness and original eligible target state. A missing index row and an immutable claim are insufficient evidence. Both native replay validators establish signed canonical content; neither retrospectively proves that a remotely received target was eligible when authored.
6. Absence is only `absentInVerifiedLocalSnapshot` after a complete existing private history has been checked. Unmaterialized or missing local history is `historyUnavailable`, not globally absent and not an empty success. Nothing creates a root on read.
7. Cancellation, account change, projection lag, bounds, unsupported contract and invalid provenance remain explicit errors with no payload. Snapshot tokens are opaque local authority bindings, not cross-device clocks.
8. The new read capability remains unadvertised until native and adapter acceptance. Full T2 remains OFF. Existing runtimes return explicit unsupported behavior; no generic-object fallback is permitted.

Heart already has internal indexed `Store.ReadOperation` and native receipt indexes. Its public `NativeTorahTargetRead` currently requires a live target. `torahopsobject/target_lease.go` holds the real settings/target locks and scans signed settings genesis history for ObjectDelete/SpaceDelete; that is a genuine deletion boundary, but still does not supply original target eligibility after destruction. A new read lease must handle several candidate targets without recursively taking the same settings lock or changing write-lock ordering.

Any already expands object seeds into every global logical variant in `object_snapshot.go`. A whole missing object is rejected by `nativeTargetRow`. `ReadWorkspaceSnapshot` retains the claims under current ACL but scans the bounded workspace; it is not an acceptable substitute for an indexed by-ID public API. A new route should use `logicalKey`, declare all target/type dependencies, repeat the closure query in one `NativeReadSnapshot`, and classify graph absence separately from malformed graph state. The current v9 runtime and its artifact-reuse checks remain untouched while the additive candidate is developed.

## Next shared contracts

### Indexed source query, pages and progress

The semantic document-source route in Any intentionally excludes block targets. Its related route can return document/block targets but returns semantic associations rather than complete operation history. These are useful native indexes, not proof of the required raw operation query. Heart lacks that reverse-source index entirely.

Define the source identity and whether the request asks for operation history or materialized associations before adding an index. Reuse canonical provider/reference identity without silently applying presentation normalization. Every candidate logical key must expand to its global variants before conflict handling. No source/target predicate may conceal a cross-target collision.

A cursor must bind account/session generation, Space, engine/runtime contract, query fingerprint and a native snapshot/index generation. Stable ordering and a fixed maximum page size are required; stale account, changed contract or unavailable snapshot returns an explicit rejection. It is not an offset into a freshly changing collection. A watermark must identify native commits actually included in the projection; Any's readiness hash identifies a local snapshot, and Heart's LocalAppliedSeq identifies local replay progress. Neither is currently the negotiated public indexed-through-commit contract. Bounded reconciliation must honor cancellation and return pending/behind without false absence.

### Backup, import and compaction

The RFC explicitly allows either a versioned encrypted logical backup stream or an explicit unsupported-data result. A new encryption format is not necessary merely to make omissions honest. Ordinary export may exclude the private host; account/Space backup must not silently report completion while dropping associations. The safe first shared contract is an explicit unsupported-data result bound to the actual export entry point, with preservation and rejection tests. That does not claim successful backup restoration or close every restore/downgrade row.

`AnyTorahArchive` is a portable canonical copy: export captures bounded object history for audit, while import creates new operations, destination mappings and current-author authority. Imported source provenance grants no rights. The executor validates targets/collisions and returns resumable receipts. It does not restore original signed history or all tombstones as native identity. The UI agent separately owns its real Files export/import/cold-reopen/re-export journey; do not duplicate that work or credit an observation-only picker test as completion.

The same precision applies to compaction. Explicitly unsupported compaction with retained signed history and rejected unsafe snapshots can be a reviewed safe policy. No automatic deletion horizon should be invented. Required rejection/preservation evidence and practical 10k bounds remain necessary.

### Causal order and negotiated iOS adapter

Both folds currently document bytewise operation/claim order. Existing `observed` references encode some causal edges; native signed change ancestry encodes more. The final shared display rule needs an explicit architecture choice and vectors for concurrent successors, missing predecessors, cycles and bytewise ties. Do not silently reinterpret a UUID, arrival sequence, timestamp or readiness hash as causality; do not discard provenance or alter canonical v1 merely to sort the UI.

Heart's generated native RPC exists, but the retained source has no generated Swift T2 binding or active adapter for it. `RPC_BOUNDARY_20261118.md` records that the ordinary Invocation wrapper throws the error and discards the rest of the response. The new adapter must preserve durable receipts and distinguish persistence from projection/account failure. Any already negotiates guarded native capabilities; keep that real negotiation and eliminate no checks. Share validation and presentation across adapters; prove each engine's native boundary once, then run only the affected iOS journeys with independently disposable state.

## Test selection and honest completion

For the first read increment, test complete same-ID variants, exact canonical bytes/provenance, live document, live block, unreachable block, entirely missing object, wrong/changed account, revoked current read access, malformed graph, cross-target collision with one denied target, candidate changes between discovery and final lock, root absence, cancellation and count/byte overflow. Native target-deletion/account races need actual engine fixtures; controller tests alone cannot establish them.

Do not rerun accepted crash, lost-reply, remove/re-add or ordinary export suites solely because this audit was written. Revisit a retained suite only when a product/source dependency that it qualifies changes. Source-only validation, compilation, native fixture execution and iOS acceptance must remain separately labelled. A successful read increment does not close the remaining sixteen-row matrix or enable full T2.
