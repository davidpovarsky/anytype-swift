# Native empty paragraph direction — source change awaiting Apple execution

This change repairs the new engine's UIKit empty-paragraph presentation. It
has been independently reviewed at source level. **No application build,
XCTest execution, simulator interaction or visual acceptance is claimed.**

## Cause and repair

`AnyNativeEditor` already resolves block direction and alignment through
`AnyNativeWritingPolicy` and the shared `PinkhaWritingDirectionPolicy`.
However, an empty attributed string has no attribute run. The generic
equal-text renderer consequently has no paragraph attributes to copy into
the empty input. The original native editor had no `typingAttributes` path.
This also loses the resolved heading font before the first character.

The existing paragraph/font/color computation now supplies both attributed
rendering and an empty-presentation cache owned by the current block ID.
The text view restores those same attributes after rendering, on successful
focus, on selection resets and before initial ordinary insertion. The
selection delegate ignores callbacks generated by that restoration. This
does not insert placeholder text, move the selection, request native
persistence or take ownership of a new focus request.

Changing the block identity retires the cache. A real marked range, the
editor's composition state or nonempty text prevents restoration. Unrelated
typing attributes are retained. The generic renderer, its existing package
tests, the Heart focus implementation and its 22-method/34-case suite remain
byte-identical. The existing Anytype components, typefaces and colors remain
the presentation source.

Wave 3 confirmed there was no active writer in `AnyNativeEditor.swift`
(HQ51 story `1220940805400426`). Read-only Git objects establish that the
original editor, renderer and renderer tests at this branch's a089 base are
byte-identical at the coordinated integration source
`a82fa890a0114990e474b48830e4a2de3e32c79d`. No Hanlin, MiniApps or Native
contract files are changed.

## Targeted tests and producer requirements

The new file is `AnyTypeTests/Pinkha/AnyNativeEmptyParagraphDirectionTests.swift`.
It belongs to the hosted **AnytypeTests** target, imports the Debug/testable
`PinkhaAnyUI` module, and contains four methods/six literal cases:

| Method | Cases | Required observation |
| --- | --- | --- |
| `emptyRenderAndFirstFocus(isRTL:)` | false, true | Real key window and responder, caret side, base direction, font, explicit center alignment, unchanged empty text/selection/undo |
| `emptyAttributeAndSelectionReset(isRTL:)` | false, true | Source direction survives native typing/selection reset; unrelated underline survives the attribute restoration |
| `compositionAndNonemptyInputAreUntouched()` | one | Actual UIKit marked range and nonempty text retain their attributes and selection |
| `reuseClearsPriorBlockPresentation()` | one | Reuse rejects the retired block's attributes and clears state for nil identity |

The next producer must bind this test file and
`AnyTypeTests/Pinkha/PinkhaTextBlockLeadingMarkerTests.swift` to the real
**AnytypeTests** Swift compilation inputs, along with the already required
focus files. The native editor source must be in the selected
`PinkhaAnyUI` product compilation. Enumeration and actual XCTest result
bundles must then establish the exact cases on that admitted product.

The existing `AnyNativeTextRendererTests.swift` belongs to the package target
**PinkhaAnyUITests**. Its three methods are unchanged; this work does not
claim they were compiled or executed by the application target. The hosted
new tests require a real UIWindowScene and do not silently skip it or replace
