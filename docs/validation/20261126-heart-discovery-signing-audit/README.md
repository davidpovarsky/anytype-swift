# Heart discovery and signing audit

Source-only audit of App15 source 379ca3568f247d2fc218ed63df24796d461713c0 and its exact native permission manifest. Every inspected Swift/project file equals that Git revision; the listed native files equal the actual manifest hashes. No product, entitlement or feature-flag edits, builds or runtime tests were performed.

## Findings

1. Launch wiring is present: AppDelegate runs AppConfigurator, whose GlobalServicesConfiguration installs and retains the DiscoveryProxyAdapter before account startup when nativeLocalDiscovery resolves true. The adapter calls the actual Lib.ServiceSetDiscoveryProxy bridge. Heart registers a notifier provider and selects provider-backed discovery at account construction. The choice is fixed for that session; provider errors do not switch to zeroconf.
2. Release is not already universally on that route. FeatureDescription sets nativeLocalDiscovery defaultValue false and debugValue true. FeatureFlags uses releaseAnytypeValue for CoreEnvironment.releaseAnytype; CoreEnvironment reads CompilationCondition, and Release project settings specify RELEASE_ANYTYPE. Persisted per-feature user defaults take precedence. Debug and Nightly normally resolve true, while a default production Release resolves false and selects Heart's raw zeroconf implementation. The feature is applied at relaunch.
3. The native Bonjour route uses DNSServiceRegister/Browse/Resolve and GetAddrInfo for the declared _anytype._tcp service in the local. domain. The app Info.plist declares that exact service. Registration uses the real peer ID and real native TCP listener port. No arbitrary service enumeration is present in this route.
4. Full LAN parity is not established: DNSServiceClient exposes only lookupIPv4 and requests kDNSServiceProtocol_IPv4; BonjourDiscoveryEngine calls only that method. The existing raw Heart implementation explicitly supports IPv6 link-local discovery for iOS en/bridge cable interfaces without routable IPv4, preserves interface scope, and uses IPv4AndIPv6 where needed. Enabling the current flag alone would therefore leave a concrete IPv6-only/cable discovery gap.
5. Lifecycle also differs by design: native discovery withdraws registration on background, refreshes on foreground, and asks the native TCP listener to pause on background. Local Network denial is reported and retried on later activation rather than bypassed. Account changes cancel the prior observer generation. These paths need affected real-device/peer validation for any production rollout.
6. The two current extension entry points do not start a Heart account: ShareViewController saves shared content and opens the main app; NotificationService decrypts push payloads from existing shared storage and does not link Services/Lib. No extension discovery installation or raw multicast call was found in their inspected source dependencies. This is a bounded source result, not a complete release-binary runtime proof.
7. Raw multicast remains a genuine reachable main-app path with the current Release default. Heart's localdiscovery.go imports libp2p/zeroconf and calls its RegisterProxy/Browse with IPv4/IPv6 interface options. The provider-backed implementation does not invoke those operations. Direct peer transport after discovery uses the existing native listener/authenticated peer exchange; this audit does not replace the independent Any-engine raw discovery audit.

## Apple policy boundary and limits

Apple TN3179 distinguishes ordinary declared Bonjour operations from direct multicast/broadcast and arbitrary Bonjour-service operations. Declared system Bonjour is not itself evidence that the app requires the multicast entitlement. Raw zeroconf remains relevant here because the current production default still selects it. The same technical note says Simulator does not support Local Network privacy; simulator success cannot qualify the real-device permission or shipping-signature behavior.

Primary source: https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy.md

No conclusion that the current Release can drop its multicast entitlement is supported by this audit. A deliberate, tested platform-discovery rollout would first need IPv6/scope parity, preserved peer discovery/handshake/sync, startup/account/background/denial handling, explicit treatment of the old fallback and the independent Any engine. Entitlement changes and final signing remain root-owned.
