## Repair

The downstream Pinkha adapter retains the legacy one-message contract and admits only the captured two-message order. Every message retains exact Space/context ownership and unknown-field refusal. The amendment must target the original object, contain no sub-object IDs, and contain exactly nine distinct qualified projection keys. Values must satisfy the native key/type contract and match deterministic protobuf bytes from the same object's complete ObjectShow read immediately before the write. This binds opaque canonical keys and both hashes to the actual preflight, rather than treating a hash-shaped string as content evidence.

The qualified native154 implementation changes only block marks. Its cache proof excludes marks, block content, lastModifiedDate and lastModifiedBy; its projection is exposed in ObjectShow CombinedDetails. Thus a changed, missing, stale, duplicate or foreign projection is refused. The original returned event is published unchanged through the original owner/generation fence, and the full block CAS/readback and cancellation rules remain. No extra RPC, native/schema edit, synthetic event or general allowance for extra mutations is introduced.

The projection contract requires READY/true and version 1; lowercase SHA256 strings; the opaque current canonical-property key; a native list of unique literal Torah property keys; and a strict JSON string mapping identities to required Hebrew and optional English labels. Current bounded JSON duplicate/UTF16 validation is reused. The extra-message profile is deliberately closed to the nine captured fields; other projections remain refused pending a separately qualified contract.
