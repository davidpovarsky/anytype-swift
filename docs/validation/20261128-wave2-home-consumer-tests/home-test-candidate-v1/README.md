The controlled HTTP fixture supplies standard installed wiki and Note declarations, the original capability defaults, one built-in Page type with the original document-eligibility response, current membership, an empty complete hierarchy, one ordinary Page row, and real ready/snapshot SSE frames. No imported Type/catalog Directory or migration mapping is constructed. The observed second all-document query proves the initial hierarchy frame reached the original consumer refresh path. The test never sets `isReady`, constructs a lease or opaque marker/binding internally, replaces the model, installs schema, or creates an object.

The one method runs with Owner and Reader fixture responses. It verifies real readiness, read-only state for Reader, Home set/readback, precise object-ID/nil-block open callback, unset/readback, and no additional open callback for an absent Home. Only the exact bound settings route is accepted. The fixture requires exact account/run request headers, returns the original 204 bound acknowledgment shape, and rejects duplicate dispatch, unbound writes, object creation, and all other mutations. The existing rejecting creation journal records an issue if accidentally used.
