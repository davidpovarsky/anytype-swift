# Explicit account stop boundary

The pinned Heart source `d98420b1113536afd08cde6de9a5816f6d27ffff`, `core/core.go:AppShutdown`, intentionally returns a NULL RPC error even when `applicationService.Stop()` fails. The prior fixture's `closed=true` therefore recorded an AppShutdown acknowledgement, not proof that account shutdown succeeded.

This follow-up calls the original `AccountStop(RemoveData:false)` first. Its RPC exposes an actual stop failure. The native fixture then invokes the original `AccountPreloadRemainingSpaces` RPC and requires `ACCOUNT_IS_NOT_RUNNING`, calls AppShutdown to finish wallet cleanup, and publishes both observations. The pinned `core/application/account_preload_remaining_spaces.go` checks the actual application pointer under its read lock before returning this exact error. This keeps the proof on the original public RPC boundary, without a fabricated middleware pointer or a private native override. The controller rejects a missing/repeated stop call, a failed stop, or a retained application even when AppShutdown reports success. No Heart source, patch inventory, runtime capability, or account data is replaced.

The focused controller suite passes 15 test functions and 43 subcases with no skips. These are rejection controls and Go formatting/syntax checks; they are not native acceptance. The previous account-pair retry (44227973270) is tied to its original pre-follow-up fixture. Any passing result from that run cannot be relabeled as proof of this stronger stop boundary.

A separate, uncommitted Apple same-source fixture is being prepared and is outside this source handoff. Its planned boundary additionally queries the original account RPC after AccountStop and requires ACCOUNT_IS_NOT_RUNNING before claiming completion. The product lookup flag remains disabled.
