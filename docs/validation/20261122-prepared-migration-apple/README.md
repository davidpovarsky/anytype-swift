# Prepared migration: first Apple acceptance candidate

This publication joins the previously qualified native object/block reservation work, bounded inline-native proof, portable migration client, and lossless archive inspector with one new Apple runtime acceptance route. It does not declare full migration complete.

The default and authorized native build paths remain available. The new candidate is selected explicitly with `PINKHA_ANY_NATIVE_ARTIFACT=verified-prepared-v1` and native version `v0.5.0-pinkha.prepared.1`. Full source patches compose the retained Any and SDK work against exact upstream revisions. Existing source patches and ordinary storage paths are preserved.

## Evidence retained without re-execution

The client has 18 actual Windows Swift methods and the archive inspector has 12 actual methods, with their original logs, source pins, rejected zero-test attempt, and audits. Native reservation, staged commit, restart, strict HTTP, inline boundary, and ordinary file readback evidence are retained in the original qualified bundles. Their platform and process limits still apply.

Four new version controls passed with unchanged before/after source hashes. Sixteen new Apple-controller controls passed with substituted Apple/native subprocesses; the original unit receipt does not contain a before/after source census. Frozen final source hashes and the original log are retained without claiming a stronger historical source binding. Swift parsing and extracted version-enum execution are distinct from Apple compilation. Windows Package manifest inspection was partial and timed out in the retained verified-v1 baseline attempt; candidate manifest execution remains for the actual Apple build.

## New Apple route

Dispatch `prepared-migration-apple` through `torah-inspector-ipados27.yml`. Leave all native reuse inputs empty for the first run. The producer publishes the exact native artifact before the separate consumer starts. A later consumer may reuse that artifact only after its producer attempt, successful producer job, source ancestry, complete source closure, artifact name, metadata, and bytes are verified.

The consumer selects exactly one new runtime XCTest. It uses the managed native HTTP server and typed client, follows the reserved object and block through five orderly SDK/store reopens within one OS process, compares current and historical readback, and rejects an application owner whose runtime lifetime ended. The controller requires the original named XCTest result, exact destination, one pass with zero failures/skips, bounded proof attachment, source/framework/dependency guards, and owned simulator cleanup. No synthetic proof can substitute for that execution.

## Open scope

Actual Apple build and execution are pending at publication. Whole Space export is not yet proven to be a coherent snapshot; the archive inspector permits no destination writes. File capability remains zero, full-tier original file migration is not implemented in this candidate, and network verification remains false. Native ACL mutation, lost wire acknowledgements, separate-process crash recovery, mounted UI behavior, physical iPad acceptance, and broader project completion remain open.

`ROOT_INTEGRATION_REVIEW.json` binds the exact frozen sources, original evidence, and these limitations. Publication also requires the shared source-retention gate and exact Git-index verification.
