## Deterministic failure and owner transition

1. The real mounted document loads through controlled HTTP and its unchanged permission/type/readiness checks. Both original editor and claims streams must be held and the attachment model must be idle and ready before selection.
2. The original UI writes its protected intent, retains the exact original creator before dispatch and calls the real Host/Engine upload. The listener accepts exactly one scoped file POST, with the expected name, MIME and seven raw bytes. It reads the actual caller record and exact original reserved journal entry; it does not create either record.
3. Immediately before returning the real HTTP201 body, the listener changes only the freshly owned journal scope directory from 0700 to 0500, checking owner/device/inode/type/mode. The actual production `openat(O_CREAT|O_EXCL)` created-entry append then fails and poisons the real journal. The test explicitly requires a non-root process so the permission barrier cannot be bypassed.
4. The listener holds the first post-ACK health request. The existing live catch is attempting its original lease check at this boundary. The test independently observes actual `journalUnavailable`, verifies the caller claim still cannot be reacquired, and captures the mounted state. A cached opaque token must still be absent after drain, so a different unexpected request ordering cannot silently pass as the intended close-path witness.
5. The test restores only that same directory's 0700 mode. Reopening must still fail while the old original protected-journal claim is held. It marks expected transport drainage, calls original presentation-lifetime revoke/drain, releases the held response, and awaits the actual `AnyNativeWorkspaceOwner.close()`. That method awaits session drainage before journal close. Journal close releases the exclusive flock; it does not imply all descriptors are deallocated.
6. Only after old connections are observed closed does the test acquire/release the caller claim, confirm cached token absence and unchanged pending JSON, reopen the **same original protected journal** and observe `.reserved`. It creates a new real session/ObjectCreator/workspace owner, mounts a new document with the **same recovery object**, and requires a different session generation plus the same caller-store actor.
7. The original pending request appears in the current model/view. The original Check action must recover through old memory export and current creator resume. The test requires the actual journal `.verified(originalFileID)`, two current info reads, one exact ranged-content digest read, final FilesV2 match and final protected pending-intent removal. The fixture rejects another upload or any upload during the replacement phase.
8. The original document object, Space, block identities and raw block UTF8 remain unchanged. The current actual mounted attachment pane is captured. Exactly one controlled upload and the same returned content SHA256 are required.

The test assembles the controlled workspace with the existing internal owner initializer and original session/creator/journal APIs. It does not invoke the production `AnyNativeApplication.connectSpace` account/runtime workflow; that complete production route remains source-bound by the separate owner-transition proof and a future genuine Native mounted journey. No ad-hoc closed boolean replaces the tested old owner's actual close or the protected journal's successful exclusive reopening.

## Bounded ownership and evidence

The listener has an independent 90-second lifetime, 512 total connections/requests, 16 simultaneously tracked connections, 32KiB accumulated request and 16KiB header/body/JSON response limits. Only the exact controlled routes are admitted. Listener startup and final socket cancellation each have five-second deadlines; mounted-state waits have ten-second deadlines. No subprocess, external server, URLProtocol replacement, global framework swap or second journal manager is used.

All accepted sockets remain tracked until their actual cancellation callbacks, including rejected late connections. Cleanup restores the owned directory mode, marks drainage, revokes/drains the active presentation, awaits the active real workspace owner close, and stops the listener. The first failure is preserved; later cleanup/evidence failures are also reported. The temporary root is removed only after actual listener cancellation, zero owned connections and restored permissions; it is retained on failure. The original caller namespace is not recursively deleted. No private Native account or credential is accessed: all account/Space/object/file identities and payloads belong to this controlled fixture.

Three JSON/PNG phase pairs are retained (`ack-with-poisoned-journal`, `reopened-original-request`, `verified-current-caller`) plus the final raw controlled request/closure trace. The trace records actual request counts, ACK response count, source hashes, content hashes, fault restoration and listener/connection closure. It does not serialize the opaque token or old creator. Visual review remains pending even if all source assertions eventually pass.
