# T5 cached native query after locally verified signed revocation

## Scope and current status

This is one new native Go test, `TestT5NativeCachedQueriesAfterSignedRevocation`,
against the exact already reviewed `r15-attachment-v1` source composition. It
adds no production patch, command schema or capability. Actual native execution
is NOT_RUN until its separate Linux CI receipt is qualified. A security failure
stays FAIL; it is never converted to a passing expected-failure test.

The existing pagination proof (44579466213, ten observations) and signed T2
private-tree authority proof (44419232954) remain retained. Neither is rerun or
relabelled as this public ObjectSearch/ObjectShow boundary. Corrected T5 UI run
44958628074 and SDK run44956239736 are independent and unchanged.

## Actual native sequence

The fixture creates one disposable native account and one Space through the
same generated byte commands used by the mobile library. It creates a real
canonical Property, the registered native Types, a hidden manifest, one source
association and a visible body block. The auxiliary template/folder manifest
slots follow the already qualified native query fixture; this scenario does not
claim complete application bootstrap or migration.

It reads the exact canonical source through the actual indexed private-membership
ObjectSearch filter and the actual ObjectShow response. It then applies three
real signed ACL records through native admission, persistence and SyncAcl:

1. Add a real second signing identity with native-derived AccountMetadata.
2. Transfer ownership to that identity and downgrade the original account to
   Reader. Prove the unchanged engine-owned account can still read the exact row
   and body, using the same populated native cache instance.
3. Rebuild the new owner's ACL signer from the original complete signed bytes,
   sign removal of the original identity, and rotate the read/metadata key.

The original middleware account/key never changes. Both native ACL validation
and the original updater are retained; no fake permission state, claimed-account
substitution, updater replacement, or suppressed cleanup is used. The test
observes ordinary queries after the native ACL verified and persisted removal.

After removal, both queries must return an explicit nonzero native error.
ObjectSearch must contain zero rows and zero total; ObjectShow must contain no
object payload. A success-with-empty response is ambiguous and fails the gate.
The current permission must be None, historical read permission must remain
true, and the read-key identity must change. Native account stop is also checked.

## What this proves and does not prove

The delivery scope is **locally verified signed ACL records in a real account**.
The new signer is a genuine key and native ACL, not a second application client.
This does not prove coordinator or network ACL transport, discovery of a remote
revocation while offline, full T2 multi-client acceptance, Apple runtime behavior
or the complete T5 criteria. Those statuses remain explicit in every receipt.

The baseline run may reveal a real access gap. A production fence may be added
only after reviewing that actual result and the relevant shared native authority
boundary; no Swift-only permission flag can stand in for native enforcement.

## Efficient build and evidence boundary

The reusable workflow builds one Linux fixture binary, then selects exactly this
one method once. It uses the pinned Go1.26.5 musl image and the already reviewed
Tantivy/genproto inputs. It restores only compilation inputs, preserves compiled
dependencies even if the actual security test fails after a completed compile,
and never reuses a test result or an application binary.

The source/patch/inventory, generated test overlay, original dependency files,
native binary hash, process ID, nonce and exact one-method output are bound into
the receipt. Raw account stores and credentials remain private. Only the owned
nonce, sanitized native observation and original log are exported after checking
them against both original account secrets. No native log is published before
that credential inventory exists.

Seven new controller tests passed in0.588 seconds with Python3.12, zero failures.
The Go fixture passed `gofmt` parsing; native typechecking/execution remains
NOT_RUN. The new controls check exact observation shape, engine identity,
signed-transition/key-rotation requirements, explicit denial, zero/extra/failed
test execution, honest failure retention and secret-safe publication. They are
controller evidence only and cannot substitute for the actual native method.
