# Heart text semantic projection

Heart's pinned AnyBlock inline codec is the source of truth. Its export syntax is not ordinary Markdown: entities, image-like syntax, literal code, and object links have different meanings. Passing those bytes directly to the destination Markdown parser can silently change content.

The new Go projection invokes the exact pinned production codec and binds its detached output to the original UTF-8 source digest, UTF-16 length, literal mode, supported mark vocabulary, and valid Unicode ranges. The Swift receiver validates those bindings. The destination converter preserves text and each UTF-16 style/link range, then re-parses with the actual destination parser and compares all resulting semantics. It explicitly refuses underline/color/object/mention semantics that the current destination renderer or native identity map cannot represent.

A bounded text block plan converts nine source text styles into the actual destination type/style vocabulary. It retains nesting, sibling lexicographic positions, heading level, list ordering/numbering, checkbox state, code language, original source JSON, and content digests. Foreign projections, unknown fields, unknown blocks, and invalid hierarchy fail closed.

## Actual execution

- Five Go methods passed using the production AnyBlock codec on Oracle Linux aarch64.
- Twelve cross-language fixture projections were generated by the built Go producer; all independently expected visible texts matched.
- Four Swift inline methods passed against those actual projections, including eight convertible fixtures and four explicit unsupported outcomes.
- Two additional Swift methods passed for nine text block styles, nested order, retained metadata, and refusal of foreign projections/unknown fields.
- Go1.27.4 and Swift6.4.3 were used. The initial offline Go resolution attempt lacked module cache metadata and did not execute tests; the bounded online verified-module resolution completed before the accepted run.

This component is a conversion stage. It does not grant native source authority, claim a full semantic source census, open destination writes, or claim full-Space migration. Original archive entries and inspection issues remain retained. Full source identity mapping, schema/history/file preservation, and actual native destination execution remain separate required stages.
