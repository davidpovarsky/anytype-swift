# Bounded inline-file Apple controller

The opt-in controller selects the new native prepared-inline candidate and one
actual XCTest. Four run-specific values bind the original generated xctestrun
to the current source commit, GitHub run, attempt and fresh nonce. The generated
target's EnvironmentVariables carries that binding; Xcode's injection and all
other original target fields remain unchanged. The descriptor stays beside the
original Products so __TESTROOT__ retains its meaning.

Admission independently requires exact current source, both original native
slices, the producer job and artifact receipt, frozen Swift package pins, one
passed named XCTest on the owned ARM64 iOS 27 simulator, 14 native observations,
four byte-exact ordinary file reads, and completed owned cleanup. Compiled
products and both original/bound descriptors are verified after execution.

The two real native owner objects allow both pending preparations to survive
the first orderly SDK/store reopen without invalidating the other's frozen
carrier dependencies. Empty and 4095-byte files, the decomposed Hebrew/Unicode
filename, the two distinct file IDs, and three distinct runtime/application
owner generations are checked. This does not prove OS process crash recovery,
lost-ack injection, network synchronization, SSE persistence or full Space migration.
