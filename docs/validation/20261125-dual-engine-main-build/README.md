## Corrected integration failures

The first actual build found a missing main-actor annotation on the nested
Any MiniApps registration owner. The next found a missing ProtobufMessages import
in the Heart sharing adapter. Both received narrow source fixes.

The third actual build compiled all app Swift, including the original-app source
capture controller and actual Lib bridge, then failed on public Swift symbols
leaking through facade typealiases. Commit ed28491255414c4aae719205e6a3e97ec01ff05a
replaced those typealiases with concrete public wrappers forwarding to the same
native application, presentation session, root view and return router. It added
the existing pure-Swift AnyHost product explicitly to the main/test graph where
the original app consumes its source-capture contracts. It did not add a second
Go runtime, force-load undefined symbols, remove native features, or bypass linking.
The subsequent complete app/test build passed.

One admission attempt stopped before any Xcode invocation because disk free
space was below the owned-process2GiB emergency floor. The later phase was admitted
using measured preceding peak consumption and a2.5GiB growth allowance, followed
by an independent0.5GiB UI-only allowance. No other owner's process was stopped.

After the app passed, the old UI projection rejected the six current configuration
entries because it expected four. The two additional entries are the previously
committed Debug-MiniAppsOwner/Release-MiniAppsOwner signing configurations.
Commit0b9c5d75fec8fa4f4e17266010f7d79a47c08b87 validates their exact identifiers
and names, preserves all six configurations, and removes only the generated
runner's implicit application binding. Pure projection controls ran against both
the exact old four-configuration project and current six-configuration project.
Both original projects/schemes stayed byte-identical; every generated scheme
reference targets only the original UI test bundle.
