# Embedded account bootstrap: debug presentation boundary

The same immutable non-nil caller that constructs this account presentation selects a constant-false presentation binding for its two original debug sheets. The sheet content also checks the same immutable nil-caller fact before constructing either admin destination. This introduces no new global mode lookup, authority, task or replacement debug implementation.

Standalone calls keep the original writable model binding and the complete original debug destination. Embedded hidden debug taps may still update their existing local model flag (and the Login logo retains its original sound); the constant-false sheet binding prevents presentation, and its guarded content does not construct the admin model. No blank or substitute sheet is shown. Auth navigation, actual Back/logout, Settings, join/login, migration and the outer session close path are unchanged. This deliberately does not delegate whole-application debug administration to an embedded account-bootstrap session.

The original InternalDebug and PublicDebug models are retained as exact source evidence. Both can export native/local-store data, start profiling and unzip a directory before awaiting Auth logout and attempting repository replacement. InternalDebug also owns Seed removal, global feature/default changes and a debug server. The closed E2 Auth wrapper would reject their unbound logout, but that does not own the earlier debug/file operations. No such execution has been performed, and no debug source is changed by this two-coordinator proposal.
