# Proposed exact event-boundary hunks — NOT APPLIED

These three complete afterimages are review candidates only. No product file, workflow or target membership changed, and no syntax/typecheck/control/native run has been performed on these candidates. The seven previously accepted E2 product afterimages stay frozen.

Account/File handlers preserve their original standalone path. Embedded preparation awaits the existing EventBunchSubscribtion.addHandlerAwaiting, coalesces concurrent callers through one retained task, and returns an internal restrictive capture only after the exact original subscription exists. A generation/identity check rejects a stopped registration that completes late. Account stop retires the returned capture and pending installation before clearing its original cancellable. The private installation keeps capture currentness aligned with actual original cancellation; it adds no native/account authority. Bootstrap must validate the returned capture after awaits and before beginning original wallet recovery. Original LoginState start/stop sequencing remains authoritative; this installation capture is a readiness fact, not a new perpetual account-lifetime parent.

The FIFO proposal adds no second event queue and emits no synthetic event. It counts accepted chunks under the same lock as yielding into the existing AsyncStream, then marks each chunk complete only after the original single consumer's awaited handlers return. A waiter captures the current frontier. Stream termination or invalid bookkeeping fails pending waits. Malformed events retain their original skip behavior and complete only that original consumer iteration. The public wait method exposes no identity or capture token and explicitly does not prove native AccountStop/import drain or future-event delivery.

The close coordinator must wait for actual old native/UI return, then this original FIFO frontier, then old presentation consumers' actual termination before permitting a new owner. In particular, a canceled native Start or a requested Task cancellation alone is not completion. A failed frontier remains a failed close and cannot unlock a replacement owner. Whole-operation task cancellation/drain and frozen view/model forwarding remain separately proposed; these afterimages do not constitute a completed account session.

The AuthService default-empty captured restriction is proposed in the sibling auth-event-boundary-proposal packet. Its parent lineage must remain intact when the registered Pinkha wrapper admits an operation.
