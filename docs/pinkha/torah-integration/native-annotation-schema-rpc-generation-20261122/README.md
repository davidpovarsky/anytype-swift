## Tool provenance

Original SDK setup installs an unversioned Homebrew protobuf package, so there is no supported historical protoc version to infer. For this new reproducible generation, the exact original SwiftProtobuf 1.32.0 `Package.swift` selects the official protoc 32.1 artifact bundle, with SHA256 `3cfb7e13baac742c7f7ba2ff835d22356af18af2b8b7c4d630aacea5eb893fb3`. The original bundle's `info.json` contains a trailing comma. The first Python archive receipt aggregator therefore failed when its strict JSON parser read that manifest. The failure and actual raw manifest remain retained. A single read-only inspection of the already downloaded archives verified their sizes, hashes and CRCs; nothing was redownloaded or edited to conceal the failure. This is not a claim that SwiftPM itself failed.

The generator uses the original package's documented `PROTOBUF_NO_PROTOC=true` switch while building `protoc-gen-swift`, and installs the exact already pinned protoc binary/include tree directly from the unchanged archive. The opt-out disables only the optional protoc binary product/dependency. The same original `swift build -c release` command executes at immutable SwiftProtobuf commit `c6fe6442e6a64250495669325044052e113e990c`; no mutable tag or unversioned install chooses its source.

Original Sourcery 2.2.6 and SwiftGen 6.6.4-alpha.0 archives and executable hashes are pinned in `TOOL_PINS.json`. Their release metadata did not supply digests, so those pins are explicitly measured hashes of the official archives. The original tracked Anytype generator's Git blob is fixed before execution; its actual SHA256 is captured at execution. ## Failure and preservation controls

The old scripts contain semicolon chains and do not consistently enable `errexit`. The wrapper supplies Bash `errexit` and `pipefail` through inherited `SHELLOPTS` and explicit Make shell settings, without editing an original script or recipe. Fresh expected generated outputs must exist after old outputs have been removed only inside the disposable copies. This prevents a successful final `mv`, `rm` or `cp` from hiding an earlier failed generator.

The proven finite `Commands` implementation from the native-defaults packet is imported by its exact SHA256. Every subprocess has an absolute remaining budget, owns its new process group and is drained before cleanup. The first termination signal raises into that existing drain; further termination signals are ignored during cleanup. The driver removes only a directory it actually created, preserves partial generated bytes on failure and uploads original logs plus a complete evidence index. The original input checkouts remain unchanged.

All candidate-versus-baseline generated changes are reported separately from baseline-versus-tracked drift. The former must stay within the reviewed RPC output families; old source/tool drift does not become an unreviewed product change. Full before/baseline/candidate source variants remain available for review. All original source/control hashes and executable hashes are rechecked after generation. No existing test is replayed, and historical schema results are not promoted into current account, body, lease, commit or ACK authority.

First activation remains held for root's review of this exact driver, manifest and workflow. Actual generated names, compile outcomes and any baseline drift remain unknown until that single run.
