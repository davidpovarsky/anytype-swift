# Focused continuation after the observed boot stall

The retained evidence does not identify the cause of the boot stall. `RUNTIME_COMPARISON.json` binds the two actual jobs, source command implementations and timings. The two jobs used the same ARM64 runner image, macOS build, Python, Xcode/Swift/SDK, developer path, iPad model and runtime build on different runner instances. The earlier boot status call took 105.105 seconds and reported an already booted device. The later call returned no output and timed out after 185.693 seconds. Its subsequent 60-second shutdown command consumed 335.547 seconds, including unusually delayed signal/drain observations. No installation ran in the continuation.

The original command helper inherited its caller's environment. The continuation explicitly passed only PATH, HOME, TMPDIR, LANG, LC_ALL and DEVELOPER_DIR. Actual original OS/session values were not retained, so this difference is not evidence of causation. Host resource pressure and CoreSimulator state were also not recorded. A timeout increase alone would not resolve these missing observations.

## Proposed source-only correction

1. Preserve the original framework source, archive, complete 2528-member inventory, nineteen-map Clang closure, 245 controls, 38 public requirements, separate producer roles and original en/he observation verifier. Rebuild only the unarchived external consumer, as in the completed continuation. No SDK build or prior test replay is required.
2. Retain the actual signed 642-file consumer app in a separately named, explicitly unqualified archive before boot. Its exact inventory, byte count, code-signature result, current control/run identity and original framework identity accompany the archive. Never insert it into or rewrite the original SDK distribution. This removes the current inability to resume a later runtime observation from an already built consumer.
3. Add bounded read-only diagnostics immediately before boot, after a failed boot-status call and around cleanup: host CPU/memory/swap/disk facts, safe OS/session values, relevant process identities without command-line arguments, and a simulator list restricted in the derived report to the owned UDID. Keep raw outputs and timeouts. No global simulator reset, daemon restart, unrelated process termination or deletion is allowed.
4. Preserve a small explicit set of ordinary macOS session variables from the caller in addition to the existing six keys (USER, LOGNAME, SHELL and __CF_USER_TEXT_ENCODING). Retain the exact selected values for comparison; do not copy the entire environment. The GitHub token stays confined to the GitHub command channel. This restores ordinary caller context without claiming that it caused the prior failure.
5. Keep one fresh owned simulator, one boot request, the existing 180-second boot-status budget, one 300-second install only after readiness, and strict en/he verification. Diagnostics must not translate a failed or timed-out command into success. Cleanup must still prove owned-process drain and simulator absence before any qualification sidecar can exist. The failed historical run remains failed.

Only new affected controls should run: safe environment selection and token exclusion, diagnostic ownership/finite command catalog, exact signed-app retention and tamper rejection, and failure/cleanup admission. The existing 24 admission/restoration control functions and their exact inputs remain unchanged and source-scoped. Any workflow admission update must prove that preservation explicitly.

This is a concrete next candidate for review, not an approved activation or an assertion that the simulator will succeed. No source or workflow change has been activated by this proposal. The current consumer .app was not retained, so the first such candidate would still rebuild that small consumer once; the framework would remain reused.
