# Original Anytype native snapshot codec — review draft

## What this increment does

`AnytypeOriginalEditorHost.captureNativeSnapshot(maximumBodyBytes:)` exports only the explicitly bound, already opened original object through its existing `PreparedEditorPageSession.owner.performRead`. It invokes the original `ClientCommands.objectListExport` with the exact Space and one nonempty root object ID, protobuf format, ZIP, native files, nested objects and archived dependencies. It supplies no state filters, no `removeBlocks`, no backlinks and no whole-Space export.

`AnytypeOriginalEditorSnapshot` preserves the resulting ZIP bytes without interpreting or regenerating its native object snapshots, blocks, IDs, marks, links or file entries. Its opaque body format is `anytype.native-protobuf-archive`, version 1. The binary frame consists of eight magic bytes, a big-endian UInt32 version, a big-endian UInt32 canonical-header length, canonical sorted UTF-8 JSON metadata and the untouched ZIP. The header records the archive SHA256/size, original export report serialized with SwiftProtobuf (including unknown fields), positive export count and captured identities. It does not claim the report's original RPC wire field ordering.

The historical provenance consists of account, Space, original root object, host profile, annotation UUID, `capturedAgainstRevision` and exact source-witness SHA256. The revision is the pre-save revision: saving revision r can produce row r+1 while the preserved capture truthfully remains against r. Decoding neither establishes current ownership nor supplies a fresh binding. Exact UTF-8 comparisons avoid normalizing distinct identity strings.

## Admission and retention

The original RPC must return a present report with `success`, a positive matching response/report count, no object/file errors and no issues. Warning or information issues are retained for review and refused by version 1. Partial, failed, canceled and unknown statuses cannot become an accepted snapshot.

Every invocation gets a new app-temporary directory created with exclusive `mkdir`. The returned archive must be a direct `.zip` child of that directory. A directory file descriptor and `openat` with `O_NOFOLLOW` prevent a symlink from redirecting the read. The descriptor must identify a regular file, the read is bounded, and size/inode/timestamps must remain stable. The original archive is neither rewritten nor deleted by this wrapper.

The return type separates immutable snapshot bytes from the transient retained archive/directory URLs. Failure after export, including loss of source ownership, returns the retained directory together with the original error. There is no cleanup API in this increment. These temporary paths are recovery evidence; they are not a durable, portable attachment store. The original Heart exporter can itself remove canceled outputs; the wrapper preserves whatever it leaves. The original Invocation throws a non-null RPC error before returning its response, so this wrapper can retain a native report only when Invocation returns that report. It does not bypass Invocation to recover an errored response.

The requested framed-body budget is capped at 65,536 bytes. This is only a preliminary bound. Maktabah's original canonical JSON envelope, which base64-encodes the complete body, has its own 65,536-byte bound. Its existing `prepareSave` validation remains authoritative. The entire native archive is refused when it cannot fit, and staging remains available; media is never silently dropped to fit. General large-media storage needs an independently qualified durable resource transport.

The production read inherits the shared original RPC dispatch authorization being implemented by the peer agent. The agreed `performRead` call passes `rpcNames: ["ObjectListExport"]`; the codec creates no separate authority or execution engine. Integration must include that shared owner/Invocation change before compiling this call.

## Deliberately unclaimed acceptance

The production API remains export and opaque byte preservation only. Separate Debug/Simulator qualification helpers now implement an original import-completion/root-map probe and a native rich-fixture comparison. Those helpers accept only the runtime's freshly created, one-use owned Space capabilities; they are not a public restoration API and have not yet executed against the native engine. No promise of object-ID preservation after import or CRDT-history preservation is made. SHA256 protects frame integrity; it is not a signature or provenance authorization. Checking the ZIP signature plus retained bytes does not constitute full ZIP-entry, native-engine import or dependency-closure acceptance.

`Object.ImportList` enumerates importer types. Original `ObjectImport` returns before asynchronous PB import completes. The PB importer introduces temporary IDs, maps them to final native IDs, and can reuse an existing object through oldAnytypeID even when `updateExistingObjects` is false. The separate qualification draft therefore requires both real completion events, an exact target-Space collection, a unique native root map and original ObjectShow. Full restoration still requires actual native execution and subsequent original editor/file comparisons; it is never inferred from RPC return or imported count.
