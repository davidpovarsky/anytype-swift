# Native protobuf import assignment observation

This isolated candidate records the ID choices made by the original Heart protobuf importer. It adds no production caller or RPC and does not change original object creation, update, file synchronization, cancellation, rollback, notification or ACK behavior. The original source pin is `d98420b1113536afd08cde6de9a5816f6d27ffff`; the preceding source audit is retained in `PROPOSAL.md`.

## Actual source changes

The internal `ImportRequest.CaptureMappingObservation` flag defaults to false. Only a true flag on the original protobuf import kind asks the converter to record source facts. The five new source-data fields and this request flag are excluded from implicit JSON serialization. Ordinary RPC requests do not expose or set the flag.

The protobuf reader copies the archived object and Space IDs before the original normalization method changes details. It retains the returned converter ID from that same call, the archive/member paths and the original selection decision. It does not allocate an alternate ID for evidence. Filtered widget/workspace records stay distinct from selected snapshots. Generated root collections and kept/deleted-reference IDs are separate domains. Legacy JSON and malformed or incomplete source records cannot produce a complete observation, while the original import continues with its original semantics.

The processor records each native destination from the exact local `id` beside the existing `oldIDToNew[snapshot.Id]` assignment. It records each internal-key alias from the existing local `newUniqueKey` beside the alias write. It never calls the provider's mutable `GetInternalKey` a second time for evidence. Every selected original and generated converter ID needs exactly one recorded native assignment. Source/converter collisions, alias-key overwrites, kept-ID collisions, unsupported records, or bounded-record truncation deny the observation only. Existing import results and side effects remain intact.

Distinct source rows that share a native destination remain distinct. The observation labels this non-injective result; it does not collapse rows into a destination-keyed dictionary. Kept reference IDs, which the original processor seeds as identity mappings, also participate in that non-injective label. Generated-only imports with no selected original source do not claim complete original-source observation.

## Completion and ownership limits

The candidate separately records successful completion of ID assignment, entry into each nonempty creation batch, each successful worker result-channel drain, and normal return from the full creation method. It installs the copied result only after the original finalization returns and all of those conditions match, the original error accumulator and response report no error, the context remains live, and the target Space still matches the value captured at the start of this execution.

The original `WorkerPool.Start` closes results only after its wait group drains. The candidate marks a drain exclusively after `readResults` exhausts that channel. Either existing early `Stop` path returns without that mark. An early Stop continues to have the original unjoined-worker behavior; this change does not repair or conceal it. A diagnostic reset at the start of `Execute` prevents sequential reuse of a processor from returning an earlier complete observation and leaves all legacy response fields unchanged.

`NativeProtobufImportMappingObservation` has unexported fields, no exported constructor or deserializer, an incomplete zero value, and getters that return copied slices. `ImportResponse.NativeMappingObservation` returns a copied value only when the original processor installed it. The copied values are historical evidence data, not admission tokens. Archive paths are labels captured by the reader, not hashes, trusted file-opening authority or an authenticated archive identity.

The observation is complete only for the selected snapshot assignments from this original execution. It does **not** prove all original mutations succeeded, bind the account or full source archive, isolate concurrent converters/providers, record every background file remap, establish a transaction/whole-graph revision, or authorize body application, durable mapping, COMMIT or ACK. Existing assignment-time file-key writes, uploads, logged fallback errors, and finalization effects remain outside that claim. The schema registrar's synchronous active-app lease is not used around this importer.
