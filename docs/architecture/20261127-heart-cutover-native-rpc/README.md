# Heart cutover: qualified native RPC and real process recovery

This delivery extends the qualified native core commit `05c2f6d4f391a5b9d3dab7efa2987afd887a5f65` with five generated RPC methods, a lossless error/result boundary, and actual process recovery evidence. Apply the core overlay first, then `current8ac-plus-core-native-rpc.patch`, to the exact retained native manifest `8ac407e75a4bfb42c359a2f72b3822c44990caedf2351d00d78315de5c96a04b`.

## Source and integration contract

The eleven-file RPC source manifest is `b98c93ff11e492e173ca2a0b93548ed4cdfb275bb4b345bd82468e55c6e481ac`. The additional protobuf types live in `pb/cutoverpb`; original top-level protobuf files remain byte-identical. The canonical generator preserves protobuf full names and wire numbers, and changes only the additive Go package metadata. Existing 1,055 gRPC function bodies and 702 gomobile function bodies remain exact. Generated registration/dispatch adds the five new methods. No existing Anytype UI or app association repository is replaced.

The methods read the legacy source, read the cutover projection, append signed cutover metadata, import a frozen association, and append an association operation. The native core owns authority and signing. Request ownership, source version/digest, deterministic claim identity, signed receipt identity, ACL and loaded account lifetime remain admission checks. `RPC_CONTRACT.md` gives precise messages, error codes and limits.

A durable write can return both a committed native receipt and a post-commit authority error. Callers must retain the disposition, claim ID, native ChangeID and complete joined issue list. They must neither return a zero result nor automatically retry. Private projection data is withheld when authority has retired. A valid frozen retry remains idempotent after sealing; a changed source/conflicting plan is refused before the idempotency lookup.

## Remaining integration boundaries

The delivery qualifies native local signing, generated gRPC, crash recovery, signed host regressions and the supplied byte boundary. It does not establish real peer transport for cutover, an Apple framework/App build, Swift client acceptance, full-space index completeness, or UI acceptance. Swift canonical generation and the ownership adapter are a separate delivery; Wave3 must build the coherent native bridge/framework and App together before enabling the new native feature. Existing App15 binaries do not contain these new methods.

The retained earlier core and migration proofs keep their original source scope. This delivery does not relabel the original failed attempts, infer peer convergence from local completion, or rerun unchanged accepted migration evidence.
